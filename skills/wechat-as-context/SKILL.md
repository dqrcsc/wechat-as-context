# 青简 · 尺素 (`WeChat as Context`) — 微信 ClawBot 双向桥接、文章收件箱与可选知识库伴读

项目：`{{PROJECT_ROOT}}`。
CLI：`bun run {{PROJECT_ROOT}}/src/cli.ts <command>`。

## 存储与知识库解耦（三种自适应模式）

本工具**不强制依赖个人知识库**，具体运行模式与落盘路径以 `doctor --json` 返回的 `vaultMode`、`vaultRoot`、`wechatArticlesDir`、`ideasSeedsDir` 为准：

1. **无知识库独立模式（`vaultMode: "standalone"`）**：未配置外部知识库（或设 `VAULT_ROOT=none` / `VAULT_ENABLED=false`）时，工具作为独立的「微信 $\leftrightarrow$ Agent 双向收发通道与本地网页归档器」运行。文章原文、防盗链图片与阅读笔记自动保存在本地归档目录；深读与推送时无需查找外部知识库节点，也无需读取任何知识库治理文件。
2. **通用文件夹模式（`vaultMode: "generic_folder"`）**：`VAULT_ROOT` 指向任意普通 Markdown / Obsidian 文件夹（无需 `00_home` 等编号目录），按需检索该目录下的 `.md` 笔记。
3. **结构化知识库模式（`vaultMode: "structured_vault"`）**：当 `VAULT_ROOT` 下存在 `00_home/`、`AGENTS.md` 等结构化约定文件时，自动联动主线焦点与关联节点。

## 查看与定位：默认不触发同步

用户说“看看我转的文章”“最近有哪些待深读的文章”时，先执行：

```bash
bun run {{PROJECT_ROOT}}/src/cli.ts list --json
bun run {{PROJECT_ROOT}}/src/cli.ts show <id> --json
```

当用户询问**非公众号链接的微信转发内容**（如转发的老师课堂笔记、备忘速记、灵感想法、近期问答或后台长任务状态）时，执行：

```bash
# 查看最近的微信对话记录（含 capture_inbox、capture_idea、manage_schedule、vault_query、delegate_subagent）与异步任务队列
bun run {{PROJECT_ROOT}}/src/cli.ts recent --json
# 仅查看最近存入 01_inputs/inbox/ 的微信收集箱速记/转发笔记（及其完整 user_text 与 deposited_path）
bun run {{PROJECT_ROOT}}/src/cli.ts inbox --json
# 查看和管理定时任务、周期早报与待办提醒（支持 list / add / run / done / cancel，自动同步 00_home/queue.md）
bun run {{PROJECT_ROOT}}/src/cli.ts schedule list --json
# 仅查看最近 Agent 异步任务状态
bun run {{PROJECT_ROOT}}/src/cli.ts tasks --json
```

汇报文章时包含 ID、标题、作者、批注 `user_notes`、处理状态 `status` / `process_level`、分诊 `triage`、是否仅为未完成模型分析的本地摘录 `isFallbackNote`、候选笔记线索（若有，未确认语义关系），以及 `error_message`（如有）。列表默认最近 20 篇，可用 `--limit` 调整；不要把这 20 篇称为全部文章。

**不要因怀疑有新消息而自动运行 `sync`。** 查看本地收件箱不会拉取微信、调用模型、写文件或发送回执。没有找到目标时说明当前本地记录范围；用户已明确要求同步时直接执行同步。

## 同步、绑定、手动导入与回退重分析

```bash
# 本地配置自检（查看 vaultMode、落盘路径、Skill 同步状态及收发队列状态）；不会验证 token 当前有效
bun run {{PROJECT_ROOT}}/src/cli.ts doctor --json
# 仅用户要求首次连接或更换绑定时使用，扫码由用户完成
bun run {{PROJECT_ROOT}}/src/cli.ts login
# 用户明确要求同步时执行
bun run {{PROJECT_ROOT}}/src/cli.ts sync --json
# 用户明确要求将公众号或外部网页链接抓取归档并初筛时使用
bun run {{PROJECT_ROOT}}/src/cli.ts ingest "<https://mp.weixin.qq.com/s/...>" --note "<关注点>" --json
# 当某篇文章因网络波动或契约校验降级为“未完成模型分析”的本地摘录（isFallbackNote: true）且用户要求补跑模型初筛时使用
bun run {{PROJECT_ROOT}}/src/cli.ts reanalyze <id> [--send] --json
```

`sync` 是有副作用的操作：接收消息、推进持久游标、抓取新文章和图片、调用已配置模型、写入本地归档/知识库、向原发送者发送接收/处理回执。对明确的同步请求，这些是该流程的预期动作；不要把它用于仅查看或检查状态的请求。手动 `ingest` 会抓取、分析并落盘，但不发送微信回执。仅要求在聊天里阅读链接时，不据此推定用户要求入库。

后台运行入口为 `src/server.ts`（可通过 `bash scripts/install_daemon.sh` 安装常驻守护服务）。守护进程与 CLI 共用数据库；遇到 `Operation busy: sync` 表示后台正在同步，不要启动更多实例争抢。

Agent 队列另由 `agent_queue` 跨进程锁串行恢复和消费；`list/show/doctor` 不重置进行中的任务。升级前先停止旧 worker，再启动新版，不能与尚未使用该锁的旧版混跑。安装器复制并渲染本 Skill，项目更新后已安装副本不会自动更新。

## 主动推送信息与文件到手机微信（Push）

当用户在 Codex 或 Antigravity 中明确要求“把这个结论/信息发到我微信上”“把这篇笔记/报告/图片推送到微信”“生成 MD/HTML/PDF 发我微信”时，使用 `push`（别名 `send`），**该功能完全独立于知识库**：

```bash
# 1. 直接推送文本信息、总结或通知（长文本或多行含特殊字符建议用 --stdin）
bun run {{PROJECT_ROOT}}/src/cli.ts push --text "<要发送的文本内容>" --json
cat <<'EOF' | bun run {{PROJECT_ROOT}}/src/cli.ts push --stdin --json
<多行文本或总结内容>
EOF

# 2. 推送任意本地文件或图片（自动识别 .png/.jpg/.jpeg/.gif/.webp 为微信原生图片，其余为微信文件附件，经 C2C AES-128-ECB 加密上传）
bun run {{PROJECT_ROOT}}/src/cli.ts push --file "<文件绝对路径>" [--text "<附带说明>"] --json

# 3. 将任意 Markdown 文件（或 --stdin 内容）自动编译为多格式（md / html / pdf）并一并推送到微信
bun run {{PROJECT_ROOT}}/src/cli.ts push --file "<note.md 绝对路径>" --formats md,html,pdf [--text "<导读说明>"] --json

# 4. 推送收件箱中某篇文章的初筛摘要或伴读笔记（可加 --with-file 或 --formats md,html,pdf）
bun run {{PROJECT_ROOT}}/src/cli.ts push --article <id> [--with-file] [--formats md,html,pdf] --json
```

- **仅在用户明确要求推送微信时执行 `push`**；常规本地查看、深读或问答不要自动向微信发消息。
- `push` 默认通过 `reply_outbox` 持久队列入队并立即尝试发送（若守护进程正占用 `outbox` 锁会自动短暂等待重试），同时在 `conversation_turns` 记录本次推送上下文与文件路径，支持用户随后在手机微信端直接追问或引用刚推送的文件。
- 执行后必须核对 JSON 返回的 `ok`、`sentCount`、`failedCount`、`missingFormats` 与 `items[].status`。若任何条目为 `failed`/`pending` 或缺少请求格式（如本机无 Chromium 导致 `pdf` 未生成），必须如实报告，不得宣称“已全部成功发送到微信”。
- v0.2.3 起，媒体入队保存内容快照，发送前核验摘要；旧版无摘要的待发媒体需重新入队，不能靠改源文件修复已入队内容。快照保存在数据库同目录的 `outbox_media/`；v0.3.0 会清理超过 24 小时且仅被已发送记录引用的快照，失败/待发记录引用的快照保留。失败发送记录不参与自动历史清理、不自动重新发送；不要让旧版与新版共用数据库发送媒体。
- `push` 显式提供的历史文件仍保留在发送列表，即使同时生成当前版本；只需当前版本时仅传当前 Markdown。此历史文件约定未变更。
- 文件追问必须定位到会话产物、明确文章或查询结果，不能拿当天目录里看似相关的文件代替。多份 Markdown 的显式格式请求逐份处理；已有 Markdown 与另传正文不一致时拒绝导出，应提供新的源文件。
- CLI 超时或非零退出，即使有日志或产物也视为失败。任务业务失败记录为 `failed`；部分格式完成仍为 `done`，但阶段和 `missingFormats` 标明缺失，不能把它表述为全部完成。PDF 只经过头尾基本完整性检查，仍需独立查看排版效果。

## 文件保护与重试语义

- **已有原文和伴读笔记不自动覆盖、不移动、不批量改名。** 数据库已有路径继续沿用；新文章通过 URL 稳定标识区分，避免同日中文标题或模型 slug 重名覆盖。
- 重复投递、重新 `ingest`、补充文字或语音批注，会保留已有文件与深读状态。批注保存在数据库 `user_notes`，不自动重新生成 `_note.md`。深读时应同时读取批注。
- 每次 CLI `idea [<id>] "<想法>"` 创建独立文件。手机“想法：...”使用消息标识去重，重放同一条消息不会重复创建想法。
- 消息批次与下一游标在同一 SQLite 事务中保存，随后处理持久收件箱。处理失败的消息保留并在后续同步重试，不能承诺服务端永久保留消息或任何情况下绝不丢失。
- 微信回执使用独立持久发送队列，最多自动尝试 3 次，重试复用同一客户端 ID。网络中断可能使远端送达结果不确定；不要宣称端到端严格只发送一次。`doctor --json` 的 `deliveryErrors`、`inboxErrors`、`lastPoll` 可查看失败记录；凭证 `configured` 不等于已联网验证。
- 抓取/分析失败的文章保留 `failed` 和错误，可在排除原因后对原 URL 再次 `ingest`；不要删除文章文件来“重试”。已完成或已有笔记的文章不会由此重写。若文章抓取成功但模型初筛降级为本地原文摘录（`isFallbackNote: true`），可使用 `reanalyze <id> [--send]` 在保留已抓原文的前提下升级伴读笔记为完整模型初筛；已完成人工精读（`deep` / `synthesis`）的笔记绝不会被 `reanalyze` 覆盖。
- 入站附件路径包含原名与内容 SHA-256：同名不同内容分别保存，相同内容重放复用。不要自行按原始文件名猜测已存路径。
- Markdown 导出的 HTML/PDF 路径含内容版本摘要；正文或嵌入的本地图片变化会生成新版本，旧导出保留。请求多格式时逐项补齐，已有 MD 不表示 HTML/PDF 已满足；PDF 生成失败不能用旧 PDF 冒充当前结果，核对返回的 `missingFormats` 和用户可见提示。显式指定历史导出时只配对同一版本，不附带已改写的当前 MD。
- AGY 生图只收集明确返回或本次预期路径的文件，真实路径须在允许的生成目录或知识库内；不扫描共享 generated/brain 目录。AGY 应将图片复制到提示指定路径，超时、非零退出或生图没有可归属图片均按失败处理。未知模型去掉 `--model` 重试后标记 default/unknown，不能宣称仍是原模型。
- `TASK_HEARTBEAT_SECONDS=0` 关闭定时进度，阶段通知仍保留；显式秒配置优于旧 `TASK_HEARTBEAT_MS`。普通启动、重载和配置工作台统一项目 `.env` > 进程环境 > home `.env`，`IGNORE_HOME_DOTENV=true` 仅跳过 home 文件。
- Agent 任务 `done` 表示执行完成、回执入队，不代表微信已送达。恢复中断任务可能重试已发生的外部动作，不能宣称严格只执行一次。
- 本地 HTTP 仅监听 `127.0.0.1`，校验 Host/Origin 和 URL。外部抓取拒绝已覆盖的私网 IP 字面量及重定向目标，但没有 DNS 地址绑定，不能视为完整的 SSRF 隔离。不要自行改成全网监听。

## v0.4.5 多附件与下载边界

须部署 v0.4.5 或对应提交后生效；更新技能不代表服务升级。

- 多媒体收集箱和灵感笔记列出全部已下载附件的相对链接；链接相对该笔记目录解析，文件名中的空格、括号、方括号、井号等经过转义。旧笔记不自动补链接，不靠扫描目录猜测缺失附件归属。
- 小于200000字节的可读文本附件仍只内嵌前8000个UTF-16码元；发生截取时，模型输入、归档及回执保留预览范围和总长度提示。原文件完整保存且可通过链接读取，本地CLI也可另行读全文。预览不等于全文分析，提示不证明CLI实际已读完。
- 入站CDN响应上限128 MiB，按下载字节（有加密时为密文）计；同时检查声明长度和实际流量。超限、断流、空响应明确失败，不以部分内容落盘。该上限不是内存占用承诺，多份附件仍可能占用更多内存。
- 原生视频临时文件按每次处理独立命名，同内容并发处理互不清理对方文件；永久图片/文档仍保留内容摘要去重约定。失败记录不因此自动重试，历史文章不重跑。

## v0.4.4 视频入口一致性

须部署 v0.4.4 或对应提交后生效；Skill 更新不操作运行中的服务。

- 微信原生视频没有可靠发布日期，原文 `published_date` 留空，采集时间另记。不得用发送时间、文件名或采集日冒充源视频发布时间；社媒非法时间戳和 YouTube 非法日期也保留未知。
- 原生视频质量中的 `totalVideos`、`processedVideos`、`missingVideos` 按消息内视频顺序从 1 编号，仅衡量视频口播转写。全部有文本为 complete，部分有文本为 partial，全部未取得为 unavailable。混合附件下载失败另有明确警告；视频 complete 不代表其他附件已解析，也不代表逐帧理解视频。
- 纯视频、混合附件收集箱、灵感归档均保存质量及转写证据。失败/空转写也会保存采集记录，不能用“已归档”推断“已转写”；完全没有可分析的附件或转写时不调用模型猜测。含视频的混合消息中，某个图片/文件下载失败不会丢弃其他视频已取得的文本。
- 原生视频按与社媒视频相同的规则清理重复中文标点；保留原始文本，专名和数字不猜改。模型只接收清理后的单份转写，临时视频仍按原有流程清理，不承诺保留可回看的视频文件。
- 小红书/抖音视频同样写解析质量：无转写为 metadata_only，区分缺流、空转写、下载错误和 ASR 失败。已明确为小红书视频但缺流时，不拿封面当图集 OCR。原文 source writer、收集箱和灵感文件均可保留可选质量字段。
- 微信原生媒体归档主要通过 `recent --json` 的 deposited_path 定位，不保证有 article ID；`show <id>` 仅适用于文章表记录。旧文件不批量补字段，旧记录不自动重跑，仍需明确授权才主动发送/重试。

## v0.4.3 采集质量与紧凑初筛

这些规则须部署 v0.4.3 或对应提交后才影响自动处理；更新 Skill 不会升级或重启服务。

- `show <id> --json` 的 `extractionQuality` 区分 `complete`、`partial`、`metadata_only`、`unavailable`，并提供受控原因。旧文件为 `null` 表示未记录质量，不等于完整；旧 metadata_only 记录只知降级，不补造历史原因。普通处理状态 `done` 不代表采集完整。
- 图集按最多 6 页一批、最多 60 页尝试，单图最多 6 MiB；核对 `totalPages`、`processedPages`、`missingPages`。缺页提示随原文、微信和伴读保留，不能把前几页概述写成“完整还原”。`complete` 仅为逐页非空结果，非 OCR 准确率保证。不要自动补抓或覆盖历史文章。
- YouTube 字幕未发现、字幕下载失败、音频 HTTP 拒绝和 ASR 失败分开记录。`metadata_only` 表示本次只有简介/元数据，不能推断作者未提供字幕，也不能以该状态判断是否值得精读。
- 来源发布日期缺失时留空并显示未知；`captured_date`、`captured_at` 是 UTC 采集时间，不能用于代填发布日期。不要自动修写旧日期。
- 无实质批注不显示空回应；初筛保留“脱水干货”等栏目。最终渲染超过 650 码点时最多追加一次压缩请求，仅压缩干货/观点中的重复解释；业务、边界、分诊及实质批注须逐字保留，统计契约、完整伴读和分诊字段不改。压缩失败/无法保真/仍超长则保留全文并提示超长；不承诺所有文章都在一屏内，HTTP 瞬态重试另行适用。
- 微信只清理已识别 UI 行组成的奖励区尾缀，抖音时间尾码需分享模板上下文。ASR 仅规范重复中文标点，变化时原文保留原始转写；专名和数字不猜改。精读须核对音频或原文证据，不把自动转写当作者确认文字。
- 发布与安装 Skill 不代表已部署；仅检查时不调用 `sync`、`ingest`、`reanalyze` 或 `push`，不重试历史失败发送。

## v0.4.0 采集与调度修复

以下行为需部署 v0.4.0 或相应代码才生效；本 Skill 更新不能代替服务升级。

- 小红书根据最终 URL 中的笔记 ID 选择页面数据，匹配失败不采用其他笔记。强制重抓旧路径时，图片仍相对实际原文目录定位，不按当前配置目录猜测。
- 重分析以当前伴读文件判定降级；旧数据库摘要不授予覆盖人工内容的权限。新伴读带生成内容指纹；非降级、指纹不匹配或没有指纹的旧 light 笔记需用户明确要求后才使用 `--force`；deep/synthesis 拒绝覆盖。生成期间笔记发生变化会停止，先阅读新内容再决定下一步。

## v0.4.9 媒体工具与恢复边界

- yt-dlp 子进程保留 HTTP_PROXY/HTTPS_PROXY/ALL_PROXY/NO_PROXY 及小写形式（包括空值），仍剔除模型密钥、Python/Node 注入参数及 TLS 密钥日志配置。不在日志或共享报告中展示代理凭据、原始 stderr 或签名 URL。

- 证书环境注入不等于 CA 已被采用：yt-dlp 默认优先使用已安装的 certifi；无 certifi 时才经 Python/OpenSSL 默认路径加载 SSL_CERT_FILE/SSL_CERT_DIR。不得用关闭证书校验解决失败。离线 CA 测试只验证证书加载，不证明真实网站握手成功。

- 常用补跑用 `reanalyze <id> --json`，只适用于 articles 表的公众号/网页/外部平台链接。`--force` 可能覆盖人工 light 内容，并可重抓缺失或 metadata_only 的外部来源，必须先阅读并取得对应覆盖授权；`--send` 是独立发送选项。deep/synthesis 和并发编辑仍保护。

## v0.4.2 发送诊断与令牌保护

以下能力需部署 v0.4.2 或相应代码；仅同步 Skill 不升级或重启服务。

- 正常发送队列最多3次尝试，第一次失败后至少5秒、第二次失败后至少15秒，连续 flush 也遵守持久退避。一次尝试中每段正文/媒体最多两次 sendmessage 请求；仍复用原 client_id 和文本分段检查点。
- 旧请求失败不得清理并发更新的令牌；优先用新令牌恢复一次，否则尝试无令牌回退。只有无令牌回退成功且原令牌 revision 未变才清理；回退失败保留令牌。重复入站、带有效时间的迟到旧消息不回退缓存。无时间消息按接收顺序，不推定服务端 TTL 或账号额度。

- `prepare failed` 只说明接口拒绝，不能直接认定令牌过期、需要重新登录或可以安全重发。先区分 getuploadurl、cdn_upload、sendmessage 与本地准备，再核对同一 outbox ID 的后续成功、内容时效和重复风险。任务完成、上传完成、最终发送接受与用户已读是不同状态。
- 历史 failed 不会因新令牌或升级自动重试；分析失败记录不授权修改、删除或补发。旧记录缺少新诊断时明确证据不足，不补造原因。严格只读取证用 SQLite mode=ro；普通 doctor 虽不发送或消费队列，数据库初始化仍可能建兼容表。

以下规则需部署对应修订代码后才会自动用于手机初筛；仅更新 Skill 不代表本机服务已改变。

- 重跑文章或进行精读时，独立背景检索应排除当前原文、旧伴读及同源副本。代码按真实路径、frontmatter 的 `source_path` / `source_url` 在排序前排除，不能只删除最终列表里的两条，也不要按标题排除其他独立文章。自写预览脚本也必须传递文章 URL 和这两个路径。
- 当前正文是作者立场的依据；知识库片段只作背景。原文没有提到的品牌、流派或架构不能归给作者；必要的类比标明“分析类比，原文未提及”。作者主张本身也不等于已证实事实。
- 转述不得加强原文逻辑：必要条件不能改为充分条件，不先虚构作者强主张再批评；作为原文引用的文字须能逐字核对。
- 保留“往往、可能、在某范围”等限定，不把“往往”加强为“根本原因”。框架把概念放在一起不证明作者混淆执行职责，未展开不等于做错；实现风险标为“分析判断”，交代触发条件与待验证点，不用“维护黑洞”等修辞替代证据。
- 观点方向一致不是效果验证。无依据的“极高、必然、将退化为”等强判断应转为带触发条件的风险假设，不推断作者在“刻意回避”。链接标题不算用户的实质问题。
- 有业务关联时，优先给一个可执行的验证候选：验证假设、正常/异常样本、对照基线与主要改动、指标、通过/失败条件，以及业务责任人如何确认规则和复核。无基线先测基线；数字阈值标为建议待确认，不虚构已批准 KPI、人员、收益或任务授权。
- 微信与伴读均直接展示验证六项要素（伴读可按子项标签展开，微信尽量融合成 2–3 句连贯短文加 `{{VALIDATION_CONTRACT}}`，无需强制拆成编号清单），不能省略验收或只放在附件。先选被测变量：测表达结构时，两组使用同一份完整的事实与规则清单，逐条核对定义、规则、例外与示例，只比较自然语言段落和结构化字段，模型、工具、案例和运行次数保持一致；测信息补充时，披露新增规则并保持表达形式一致，不能把收益归因于结构化表达。建议样本量需确认，历史审批结论需独立复核。提出值得检验的业务假设后，默认 process_later；若只选 reference，须解释为何无实质后续价值。
- 运行前明确指标分子分母、改善门槛及误报等约束，未批准门槛标“建议阈值、待确认”，“明显改善”不能单独作验收条件。小样本不宣称统计显著。失败仅表示本次样本、模型、规则与配置下未观察到预期增益，不推出必须使用规则引擎或未比较架构更优；信息不等量、标注或样本不足时标“证据不足/试验无效”，不能证明方法无效。通过也只支持该范围继续验证。
- 固定差值是业务门槛，不是波动范围或显著性依据；无重复测量/统计估计就写尚未估计。分清百分点与相对提升（80%到92%为12个百分点、相对15%）；分母为0不判定，基线为0时相对变化不可计算。
- 初筛用一份 `validation_contract` 统一指标分子分母、改善方向、单位及建议门槛，程序把同一段统计口径插入微信与伴读。模型两份正文各保留一个 `{{VALIDATION_CONTRACT}}`，其他位置不再生成本试验的数值门槛。缺少字段、单位非法或插入位置不唯一时明确降级；无试验用 null。详细格式见项目 `docs/article-analysis.md`；这不是自动统计检验，不能把共享段落的一致性视为所有分析都正确。
- 业务验证旁文若重复“显著、波动范围、置信区间、百分点、相对提升/下降”等统计表述，会触发降级，避免共同段落正确但旁文再次越界。短版字数仍属生成目标；若真实输出超长，不能宣称已一屏展示。人工精简预览要明确标注编辑版，不冒充模型原样返回。
- 分开判断“逐段精读价值”和“场景验证价值”。仅作表达参考且无实质未决问题可选 reference；与当前工作相关且需研究/对照/场景验证选 process_later；process_now 还须明确即时请求或紧迫性；材料不足以可靠判断时 keep_raw。不要以短文、技术细节少覆盖业务决策价值。
- 预览仅调用分析函数，不运行 ingest/sync/push 或重新处理队列；用只读数据和临时结果文件比对原文、笔记、文章状态与 outbox，不把模型输出自动写回。对外模型调用遵循用户已明确授权的材料范围与目的地。

## 文章深读与观点沉淀（自适应有无知识库）

1. 用 `list/show --json` 定位文章，读取实际 `source_md_path`、`note_md_path` 和最新 `user_notes`。先检查文章是否已成功抓取，不把失败或空路径记录视为完整原文。
2. 原文是证据；正文不改。深读只在用户请求范围内追加/合并伴读笔记（`_note.md`），保留已有分析，不整文件替换。
3. 检查正文引用的关键图片。图片下载可能失败并保留远程链接；无法查看时明确说明，不编造图中信息。
4. **按 `vaultMode` 自适应处理关联上下文**：
   - **无知识库模式（`standalone`）**：直接围绕文章核心论点、关键证据、逻辑局限与用户 `user_notes` 开展深读，无需检索外部知识库节点。
   - **有知识库模式（`generic_folder` / `structured_vault`）**：先遵守目标知识库的 `AGENTS.md` 和目录级 `instruction.md`。将数据库 `related_vault_nodes` 或伴读 frontmatter `candidate_vault_nodes` 视为检索候选，查找实际存在的笔记并阅读相关全文（不存在的节点不作为证据）。无候选时按观点与问题检索，不必强行链接。核验支持、修正、反驳或适用边界，解释关系后才在用户授权范围内写具体链接；片段不足时标为待全文核验，不自动建立双向关系。
5. 若配置背景快照，精读时核对最新来源和阶段；旧笔记或初筛分析不覆盖当前有效规划。区分作者观点、用户既有观点、当前分析与待验证假说。用户确认或讨论形成个人判断后，可执行 `idea [<id>] "<想法>"` 沉淀想法，不要把模型候选观点冒充用户观点。
6. 确认伴读笔记更新成功，再按实际分诊执行：

```bash
bun run {{PROJECT_ROOT}}/src/cli.ts triage <id> <keep_raw|reference|process_later|process_now> --level deep
```

`triage` 会显式修改原文与伴读笔记的 **frontmatter** 和数据库状态，保留正文。`deep` 与 `triage` 是不同维度，不必将每篇深读文章都改成 `reference`。执行后用 `show --json` 与文件内容核对结果；写入失败应报告，不宣称完成。

手机端 `deepen` 的模型回答不会自动重写 `_note.md` 或把 `process_level` 升级为 `deep`；桌面 Agent 应在实际更新笔记后才标记完成。

## 能力与验证边界

ClawBot 接口由本地代码实现；语音仅在接口已提供转写文本时可读。公众号抓取先尝试 HTTP，再尝试本机已有 Chrome 类浏览器；验证码、删除文章、网络异常可能导致失败。外部网页的 Jina Reader 兜底默认关闭；开启 `ALLOW_JINA_FALLBACK=true` 会把包含查询参数的完整 URL 发给第三方，实际来源记录为 `jina_reader`。

图片与受支持的小型文本附件可提供给 API 模型；PDF 等附件目前没有内置正文解析器。先尝试能读取本地附件的 CLI；CLI 不可用或失败时，保留文件和“已归档，未解析”说明，不用只有路径的提示词生成内容提炼。混合附件中只要包含 API 无法读取的文件，也不能声称 API 已分析全部内容。

模型配置按 `LLM_API_KEY`、`OPENAI_API_KEY`、`DEEPSEEK_API_KEY`、`GEMINI_API_KEY` 顺序选择。文章初筛失败可使用启发式摘要，其他任务不保证相同降级行为；联网搜索失败可重试 Fast 搜索，仍失败就报告错误，不冒充搜索成功。Gemini 搜索请求保留图片输入。回执长度没有严格的 300 字保证。

回归验证：`bun run --cwd {{PROJECT_ROOT}} test`；专门的隔离验收为 `bun run --cwd {{PROJECT_ROOT}} test:isolation`。入口创建不含 `.env`、`data/`、`.git/` 的临时源码副本及独立 HOME，父子进程使用测试数据库与网络替身；直接 `bun test` 被拒绝。监听边界测试只使用本机随机端口。测试临时目录会打印并保留，不自动清理。

不要把 `push --queue-only` 当作测试隔离：写入真实数据库后后台服务仍可能发送。不得绕过隔离入口在部署目录运行探针或直接执行测试文件；不要为测试清除、重试真实历史失败记录。
