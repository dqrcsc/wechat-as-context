# v0.2.4 测试隔离修复与验收

## 问题与修复范围

此前 CLI 回归通过环境变量指定临时数据目录，但正式配置加载优先使用项目 `.env`。在部署目录执行测试时，项目中的 `WECHAT_CONTEXT_DATA_DIR=./data` 可以覆盖临时目录。`push --queue-only` 随后把测试文本写进真实 outbox，后台服务仍可能消费它。仅断言 CLI 返回 `ok` 不能证明写入了正确数据库。

本版保持生产配置顺序、发送行为及 push 历史文件约定不变，只修改测试入口、测试守卫、回归、CI 和文档。没有增加生产环境测试开关，也不清除或重试历史失败记录。

## 使用方式

```bash
bun run test                         # 全量隔离测试
bun run test tests/isolation.test.ts # 仓库相对路径，支持定向测试
bun run test:isolation               # 合成部署环境的外层哨兵审计
bun run typecheck
```

直接 `bun test` 在执行测试逻辑前拒绝并提示正确入口。测试文件与进程探针还显式导入守卫，避免从其他工作目录启动时遗漏 bunfig preload。不要绕过入口或直接运行探针。Bun 本身可能在入口前自动加载当前目录 dotenv；测试 runner 会丢弃继承环境，并使用 `--no-env-file` 启动隔离进程；如需连启动器也禁止自动加载，可使用 `bun --no-env-file run test`。

入口打印独立临时根目录并保留排错文件，本版不自动清理。HTTP 监听边界测试使用回环地址的随机测试端口；不需要部署服务、微信凭据或真实模型。

## 隔离措施

1. `tests/support/workspace.ts` 仅复制 `src/`、`tests/`、`skills/`、README、package 和 bunfig。`.env`、`data/`、`.git/` 不复制；源码输入中的符号链接拒绝。依赖通过 `node_modules` 链接复用，不安装新的包。
2. 使用新的 HOME、TMPDIR 和白名单环境；不继承模型 Key、代理、运行时注入参数或应用数据路径。生产配置优先级因此可以原样测试，不必引入绕过逻辑。
3. `tests/support/isolation.ts` 验证隔离目录标识，限制 SQLite 构造器、`Database.open` 和应用使用的同步文件读写路径。真实路径检查拒绝越界及逃逸符号链接；拒绝 `ATTACH`、`VACUUM`、扩展加载及修改 SQLite 文件目录的 SQL。
4. 默认 `fetch` 直接抛错，不调用原网络函数。测试可显式替换为响应替身；恢复 fetch 后仍是阻断实现。真实外部命令被拒绝；允许的 Bun 子进程强制携带守卫和 HOME/TMPDIR，即使调用方传了空环境。
5. CLI 离线推送回归额外查询指定夹具数据库，验证文本、`pending` 和 `attempts=0`，不再只检查 CLI 的成功响应。

这些措施保护仓库当前的数据库、同步文件、fetch 和进程调用链，防止测试意外使用部署资源。它们不是操作系统沙箱，不用于执行恶意测试或绕过守卫的任意代码。新增 I/O 入口时必须同时更新守卫及回归，不能用真实微信验证隔离。

## 验收证据

- 修复前，在全合成环境复现：项目 `.env` 指向哨兵库，CLI 环境变量指向临时库，执行 queue-only 后哨兵 outbox 从 0 变为 1。
- 新增 6 项回归覆盖：假部署配置与数据不复制、CLI 只入队夹具、SQLite 路径/只读/URI/符号链接边界、文字与媒体请求本地阻断、SQL 次级文件入口、空环境子进程和正常 mock 对照。
- `tests/verify-isolation.ts` 从守卫外创建带三条合成失败记录的哨兵库及项目/home 配置，运行隔离测试后逐字节比较数据库、WAL/SHM 和配置。还验证裸 `bun test` 与外部库 `ATTACH` 被拒绝，哨兵保持不变；CI 单独执行此审计。
- Bun 1.3.14 全量 **120 项测试、602 个断言通过**；定向隔离 **6 项、37 个断言通过**；外层哨兵审计、TypeScript 类型检查、差异检查和文档相对链接检查通过。
- Spec 复核发现的 `ATTACH` 逃逸已补回归并验证阻断；Spec / Standards 最终复核无阻断项。
- 本轮验证仅使用研究仓库与合成临时数据，没有操作部署服务、真实数据库或那三条历史失败记录，没有真实微信发送，也没有更新全局 Skill。

发布前仍须确认精确提交的 GitHub CI 通过。发布不等于部署，已运行服务不会因本次发布自动升级。
