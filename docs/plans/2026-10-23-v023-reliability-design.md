# v0.2.3 十项可靠性修复

用户已批准上一轮只读复查中的十项确定缺陷及对应修复方向，明确排除 F11 push 历史文件约定。本设计不扩大到心跳、DNS、权限模型或全仓重构。

- F01：移除当日目录猜测及委托纠正入口的同类捷径。发送只能使用会话/明确文章/查询结果；无法定位就报告失败。
- F02：媒体入队时复制内容到数据库目录下的内容寻址快照，保留文件名；记录摘要并在发送前校验。旧无快照条目不宣称已固定版本，要求重新入队。增加兼容性的 outbox 摘要列，实际用户数据库由用户未来运行新版时升级；此次只操作测试数据库。
- F03：所有 CLI 后端的非零退出和超时均失败，继续已有降级链。
- F04：PDF 先写临时路径，检查退出、超时、PDF 头/尾基本完整性，再原子发布；缓存执行相同检查。保留被替换的损坏文件，不以此宣称完整 PDF 解析或视觉验收。
- F05：已有 MD 与显式正文冲突时拒绝输入，避免静默覆写或同批内容分叉；相同正文允许复用。
- F06：显式格式请求按每份文档处理，聚合缺失；保留无格式重发独立附件行为。
- F07：新会话产物路径使用 JSON 数组；读取旧值优先识别真实单路径，再兼容所有路径均存在的旧分隔列表。不对破损记录猜测文件。
- F08：执行结果增加 success/partial/failed outcome；失败记录 failed，部分完成在阶段中说明，回执送达另行统计。
- F09：Key 自动发现与普通配置加载共用项目/进程/home 来源顺序与忽略规则。
- F10：配置刷新放在 drain 的 try/finally 内；成功加载才更新状态，错误恢复后同实例继续消费。

成功标准：每项旧复现有失败回归，补正常对照；隔离测试、全量测试、类型检查、代码复核通过；对应 GitHub CI 成功后发布。不得操作本机服务、真实微信/CLI/浏览器、用户知识库和真实凭据。
