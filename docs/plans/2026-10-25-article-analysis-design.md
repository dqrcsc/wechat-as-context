# 观点与业务驱动的文章初筛

用户已确认采用「提示词＋可配置背景材料」方案，微信直接展示较完整分析。

## 输出与边界

- 保留批注回应、核心提纯、分诊；将文件匹配改为观点碰撞，新增业务与规划启发、边界与待验证。
- 微信建议 800–1400 字，不为长度凑内容；完整分析直接发送，沿用现有超长消息分段。
- 比较补充、挑战、适用边界与新问题。业务关联遵循问题→启发→方案调整→最小验证，只选最相关的一两个场景。
- 区分作者主张、用户既有判断、分析推断与待验证假设。无背景或无关联时直接说明，不虚构。
- 初筛不展示具体笔记链接，不自动建立语义关系。保留检索候选供精读回溯；精读查证原文后解释支持、修正、反驳关系。

## 背景配置

新增可选 `ANALYSIS_CONTEXT_FILE`，指向本地 JSON 快照，与知识库开关独立。相对路径以项目根目录为准，支持绝对路径和 `~`。默认不读取、不扫描公司文件。

`version: 1`，`entries` 包含 `kind`（viewpoint/business）、`topic`、`status`（current/planned/exploring/historical）、`updated`（日期）、`summary` 和 `source`（溯源字符串）。同一 kind/topic 取最新版本；最新版本标历史则整组退出，同日冲突整组不采用并告警。来源是溯源信息，不自动打开、递归加载或执行。

规划内容不能当作已交付事实；快照优先于关键词命中的旧笔记，但不替代对现实的验证。文件错误、超限、缺失均可见降级，正常文章归档继续。公开仓库只提供通用示例，私有背景单独保留，部署生效需另行授权。

## 验收

通过隔离回归验证配置路径、版本选择、冲突与错误、独立模式、提示词契约、候选溯源、无模型降级、完整长消息入队及精读阶段；不调用真实模型或微信，不操作部署服务和历史失败记录。自动测试不能证明模型每次都会正确理解业务；保留人工语义验收样例与限制。
