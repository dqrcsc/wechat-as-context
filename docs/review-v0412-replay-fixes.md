# v0.4.13：公开材料复验的两项 P2 修复

基线：v0.4.12 / `8336c43be375764130d39e4349db5404fc497db1`。日期：2026-11-13。

## 问题与成功标准

前次隔离复验观察到：YouTube #105 的源站字幕轨道声明为 `zh-CN` / 中文（中国），实际获取的长篇正文无汉字、以拉丁字母为主；这不是已证明的选错字幕轨道。抖音 #80 则返回“于20261113发布在抖音，已经收获了0个喜欢，来抖音，记录美好生活！”模板，不能将其视为作品正文或发布时间证据。

本次验收要求：保留来源声明及字幕原文，显式提示明确冲突；平台模板不进入作品标题、正文和图集 OCR 上下文；可信旧标题仅用于识别，不能充当新正文；有效字幕、作品文案、ASR 与 OCR 保持可用；诊断贯通存储、初筛与伴读。

## 实现边界

| 问题 | 行为 | 诊断 |
| --- | --- | --- |
| 中文字幕声明与拉丁正文冲突 | 对 `zh` / `zh-*` 轨道检查：没有汉字，至少 200 个 Unicode 字母、40 个 ASCII 字母词组，且拉丁字母占字母总量至少 98% 时标记；不改字幕、不改变轨道选择，不自动判定为英语或翻译 | `caption_language_mismatch`；来源标签保留名称、代码和自动字幕标识，并提示语言待核验 |
| 抖音平台模板污染 | 对作品 desc、SEO name、页面 og:title/description 逐项清理后选择有效候选；识别独立模板与末尾 SEO 模板，保留真实内容引用模板的情况 | `douyin_template_text_filtered`；不推断模板日期为发布时间 |
| 仅剩旧标题 | 排除模板与通用占位标题；有效旧标题仅填 title，旧摘要不填正文。缺少有效文案和转写时明确提示；连有效旧标题也没有则抛出获取失败 | `douyin_content_unavailable` + `metadata_only`；不依据标题推演观点或业务启发 |

语言检查是保守启发式，短文本、中英混合、非中文声明及其他文字混合不据此定性；未触发警示不代表语言已核验。`complete` 仍只描述材料获取，不保证语义或源站标记准确。初筛模型提示说明这些边界；程序独立在回复和伴读前附加警示，防止模型漏写。

模板过滤采用已识别格式，不试图删除所有宣传性文案。图集继续按 OCR 页覆盖标记；视频有可用转写时保留 complete/partial；过滤模板本身不等于整篇内容不可用。原有身份校验不放宽。
