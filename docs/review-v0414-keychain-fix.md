# v0.4.14 macOS 匿名浏览器初始化修复（v0.4.15）

## 问题与依据

#80 的公开材料隔离排查中，导航超时并不总是代理或源站无响应。失败对照的 Cookie 持久存储加载开始后一直没有完成；仅增加 mock keychain 后，加载在 109–165 毫秒完成，目标详情自动返回。恢复所有原有代理和导航默认值、仅保留该参数，也连续两次取得文案与媒体。

该证据定位的是本次 macOS 临时匿名浏览器的初始化路径，不证明每一次导航失败都由钥匙串导致。未检查或修改真实钥匙串条目，也不将未直接观察的权限对话框当成已证实的具体根因。

Chromium 官方 macOS 浏览器测试采用同一开关，目的是避免阻塞式权限提示：[test_launcher_utils.cc](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/chrome/test/base/test_launcher_utils.cc)。

## 最小修复

新增 `chromeProfileArgs(profileDir, ephemeralProfile, platform)`，集中生成原有 user-data-dir 参数，并仅在 **platform=darwin 且 ephemeralProfile=true** 时增加 `--use-mock-keychain`。

- 抖音 CDP 在创建新的临时目录后显式使用匿名模式。
- 已有 DOM 渲染器使用实际 ephemeralProfile 参数；默认持久目录、可能复制 Cookie 的会话仍不添加该开关。
- Linux/Windows 和没有明确创建匿名目录的其他入口不改变；不按目录名字是否带 tmp 推断匿名性。
- 不引入 `--no-sandbox`、固定代理、TLS 豁免、真实钥匙串写入或额外重试。CDP 请求5秒、观察25秒、无详情请求时约12.5秒单次重载、总期限60秒均保留。
- 获取失败仍沿用 v0.4.14 受控诊断，作品 ID 校验和 SEO 片段证据边界不变。

此参数不应套用到真实登录/持久浏览器资料目录，否则可能影响读取依赖真实钥匙串加密的 Cookie。此次没有顺带重构其他浏览器入口。
