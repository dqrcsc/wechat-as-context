# v0.4.13 抖音公开材料复验修复（v0.4.14）

## 范围和成功标准

修复已确认的 SEO 简介遗漏、浏览器失败原因丢失，以及此次检查发现的媒体判定和异步响应收集问题。以合成回归、公开页面读取和隔离浏览器实验分别验证，不把其中任一种当作所有渠道端到端成功。

验收条件：身份校验不放宽到其他作品；SEO 片段有明确证据边界；浏览器失败可定位阶段且不泄露响应/签名 URL；等待边界附近的已开始响应读取能完成；音轨和空图集正确选择分支；原始材料、私有配置、未提交修改与历史 failed 保持不变。

## 确认的问题及修复

| 问题 | 原行为 | v0.4.14 |
| --- | --- | --- |
| SEO 片段遗漏 | VideoObject 自身没有 URL 就整项弃用，即使页面与面包屑已指向目标 | 仅在页面身份已验证、唯一 VideoObject、唯一面包屑及正确末级 ID、连续顺序且无其他作品冲突时接受无引用对象；对象显式空/无效/冲突引用仍拒绝 |
| 片段证据范围 | 恢复的网页简介可能被误认为全文 | 优先使用有效 name，其次 description，清理已识别模板，最多 2000 字符；标注 `douyin_seo_excerpt`，采用页面兜底时再标 `douyin_seo_page_identity`；标题和正文标示简介片段，原文/微信/伴读保留警示 |
| 浏览器诊断丢失 | 多种失败返回 null 或仅输出任意异常 | 返回固定 `douyin_cdp_*` 原因，区分启动、端点、标签页、连接、导航、HTTP/TLS、详情响应、身份和媒体；贯通提取质量、日志和完全失败错误 |
| 媒体存在判定 | 空 images 数组阻断兜底，只有有效音轨仍重复启动浏览器 | 按目标详情中的实际 HTTP(S) 图像/视频/音频 URL 判定，安全处理畸形列表 |
| 已开始的响应被遗漏或覆盖 | 观察窗口末尾启动的读响应可能未完成；后续受限详情可能覆盖已有媒体 | 停止接收新事件后等待已开始读取（仍受 CDP/总期限约束）；后到的仅元数据响应不覆盖有效媒体；清理事件监听 |

完整音频转写和不完整的网页简介可以并存。`complete` 不消除 SEO 片段警示；片段未提及不能推断原作者未展开。媒体只从匹配作品详情中获取，不使用 DOM 中的占位视频。浏览器观察到请求后不因该请求结束而误作“从未请求”触发重载。

## 单因素隔离实验

2026-11-13，对同一公开抖音作品进行 10 次顺序实验。每次使用新的匿名浏览器配置，不复制登录 Cookie；独立 HOME、无模型密钥、文件沙箱阻断部署、知识库和用户私有目录。第二轮反向执行顺序以减轻顺序偏差，但不能消除时间、服务端风控和网络波动。

固定对照条件：显式指定当前系统代理、CDP 请求期限 20 秒、导航返回后的观察窗口 55 秒、关闭重载、总期限 90 秒。每个变体只改一项。所有组都持续收集浏览器 stderr；诊断进程为适应外层 macOS 文件沙箱使用了相同的浏览器沙箱适配，这些条件不进入产品默认值。

| 组别 | 相对对照唯一改动 | 第一轮：结果 / 总耗时 | 第二轮：结果 / 总耗时 |
| --- | --- | --- | --- |
| 对照 | 无 | 失败 / 21.791 秒 | 失败 / 21.440 秒 |
| 代理 | 不传显式代理标志，交由浏览器继承 | 失败 / 21.497 秒 | 失败 / 22.620 秒 |
| 请求期限 | 20 秒 → 5 秒 | 失败 / 6.494 秒 | 成功 / 14.210 秒 |
| 观察窗口 | 55 秒 → 25 秒 | 失败 / 21.543 秒 | 成功 / 10.100 秒 |
| 重载 | 无详情请求时在观察约 12.5 秒单次重载 | 成功 / 21.122 秒 | 成功 / 10.797 秒 |

成功的四次都取得匹配详情、795 字符文案、1 组音轨与 3 个主视频候选地址；其余六次为 `Page.navigate` 请求期限触发，没有观察到详情请求。总耗时包括浏览器启动，不等于单次导航耗时。

**不能从此表推断“延长超时有效”“重载必然有效”或“必须显式代理”**：每组只有两次，对照两次均失败；重载组第二次在总耗时 10.797 秒已成功，尚未到重载时点。请求期限 5 秒组也有一次成功。早期诊断脚本的 `navigate_done` 打点位置有误，已排除该字段，不据此计算导航时长；上表采用进程总耗时、实际详情响应和最终结果。

结论：本轮不调整生产默认代理、CDP 请求 5 秒、观察 25 秒、12.5 秒无详情请求时单次重载和总期限 60 秒。也不将诊断用的 90 秒、显式代理地址、持续 stderr 适配或浏览器沙箱参数带入产品。要判断这些因素，需要更多配对重复与更稳定的网络条件；当前修复不承诺 #80 每次都能实时取得音轨。
