## 升级与兼容性

1. 停止旧 worker/守护进程，再启动新版。旧版不获取 Agent 队列锁，混跑不能获得本次互斥保证。
2. 无数据库 schema 迁移；复用现有 operation_locks。旧附件、笔记、导出不移动或删除；新附件及导出名称会变化，调用方须使用实际返回路径。
3. 需要普通网页第三方兜底时显式配置 `ALLOW_JINA_FALLBACK=true`。这会把含查询参数的完整 URL 发送给 Jina；默认失败时不会自动外发。
4. 对 PDF 未解析、missingFormats、pending/failed 回执如实显示。任务 done 仅表示执行完成、回执入队，不能据此声明微信送达。
5. 本地 HTTP 客户端使用 `note`、`files`、`formats`；修正旧字段后再重试。需要更新已安装 Skill 时重新运行安装流程，本轮只更新仓库模板。

## 尚未解决或未实测的边界

- 队列锁以 PID 存活判断，没有租约、心跳或超时抢占。PID 复用、进程存活但卡死仍需人工处理。进程在外部动作完成后、记录完成前崩溃，恢复可能重复该外部动作；没有 exactly-once 保证。
- URL 校验并未固定 DNS 解析结果，域名解析到内网及 DNS rebinding 不在这次修复的完整防护范围。浏览器与 CLI 也未增加网络沙箱。
- 产物发现已收紧，但仍基于显式路径与时间窗口，未建立每任务独立产物清单。CLI 现有高权限启动参数、配置 API 返回实际 Key 的行为尚未改动。
- 版本摘要能区分不同源内容，不是 PDF 质量验证。真实微信送达、第三方模型/CLI 兼容性、复杂 Markdown 排版和 PDF 视觉效果需独立实机验收。
