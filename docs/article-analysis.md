# 观点与业务驱动的文章初筛

v0.3.0 的微信分析目标为 800–1400 字。v0.4.0按用户反馈改为约 450–650 字的紧凑初筛，目标约一屏，实际受字号和设备影响；详细论证留在伴读。字数是提示词目标，不是机械截断，超过 2500 字符仍沿用发送层分段。代码或 Skill 更新不代表本机服务已升级。

## 六个分析模块

1. 批注回应：有批注才写，回答关注点，承认原文未回答的问题。
2. 脱水干货：核心判断、推理和证据，区分作者主张与事实；微信只留一两个要点。
3. 观点碰撞：比较既有判断与新材料，说明补充、挑战、边界或新问题；不再以“契合某篇笔记”代替分析。
4. 业务与规划启发：问题→文章启发→可能调整→最小验证。选最相关的一两个场景，不要求每个规划方向都关联。
5. 边界与待验证：证据、实施前提、反例与失败条件。
6. 分诊与下一步：判断是否值得精读及具体追问，篇幅短不自动等于低价值。

无背景或无直接业务关联时明确说明；模型无凭据、调用失败、JSON 无效或缺少正文时输出标明“未完成模型分析”的原文摘录。降级不会虚构观点碰撞或项目承诺。

## 配置本地背景

复制 [通用示例](../examples/analysis-context.example.json) 到私有文件，例如项目 `data/analysis-context.json`（该目录已被 Git 忽略），将虚构示例替换成自己的有来源内容，然后配置：

```dotenv
ANALYSIS_CONTEXT_FILE=./data/analysis-context.json
```

- 相对路径基于项目根目录，支持绝对路径和 `~`。空值不加载任何背景文件；与 `VAULT_ENABLED` 独立，无知识库也能使用。
- 配置优先级仍为项目 `.env` > 进程环境 > home `.env`。配置入口为 `.env`，本版没有新增 Web 表单。
- 每次初筛或精读重新读取快照，不做缓存；更换文件路径需由原有配置重载流程读取。发布不等于部署，不能据此认为已运行服务已采用新版。
- 快照中的选中条目会与文章一起交给所配置的模型，并随伴读笔记保留溯源副本。只放允许交给该模型的资料；公开仓库不存实际公司快照。
- `source` 只是一条溯源字符串，可填写本地文档、讨论记录或网址；程序不打开、联网、递归跟随该引用。源文档改变不会自动更新快照，维护者需更新摘要与日期。

### 格式与状态

根对象必须为 `{"version":1,"entries":[...]}`。每条必填：

| 字段 | 意义 |
| --- | --- |
| `kind` | `viewpoint`（有来源观点）或 `business`（业务问题/规划） |
| `topic` | 稳定主题标识；同 kind/topic 视为同一条背景的版本，最多 120 字符 |
| `status` | `current` 当前判断/事实；`planned` 已确认规划；`exploring` 探索；`historical` 历史/退出 |
| `updated` | 该版本的依据日期，合法 `YYYY-MM-DD`；不是实时核验日期，不用未来排期代替 |
| `summary` | 判断或业务问题、适用范围、阶段、约束，最多 1200 字符 |
| `source` | 支撑上述摘要的来源，最多 600 字符，不自动加载 |

`planned` 不代表已交付，`exploring` 不代表已批准任务；`current` 也只是该日期快照的记录。要同时保留不同场景或假设，请使用不同 topic，不用同一 topic 存相互独立的事项。

同一 kind/topic 只采用日期最新的版本，无论输入顺序。最新条目为 `historical` 则该主题退出，不复活旧版；最新日期存在不同条目则整组不采用并告警，完全重复项去重。显式背景优先于关键词检索命中的旧片段；这是提示词中的依据优先级，不能保证模型每次都正确处理语义冲突。

文件最多 64 KiB、40 条（包括历史），选中条目 JSON 最多 16000 字符。缺失、不可读、无效版本/日期/状态或超限时整份文件不采用，微信与笔记附提示，文章归档继续；不静默截断后冒充完整背景。

## 初筛与精读的边界

- 初筛提示词不接收候选笔记的文件名与命中分数，只接收内容片段用于比较；焦点和背景本身仍可能包含来源信息。提示词禁止在正文罗列具体笔记标题/路径，输出层抑制 WikiLink、Markdown 笔记链接与已知候选路径，不保证识别所有自然语言引用形式。
- 数据库 `related_vault_nodes` 保持兼容，记录真实检索候选，不采信模型生成的新节点。该字段不是已经确认的知识关系。
- 新伴读 frontmatter 的 `candidate_vault_nodes` 使用普通字符串，不创建 WikiLink；正文不再列“关联知识库节点”。到原文存档的来源链接保留，背景来源另以转义的快照保留，便于追溯。
- 桌面精读按候选查找实际存在的笔记并阅读全文，核对支持、修正、反驳或适用边界，解释关系后才写链接。不得仅凭同词、标题或初筛结论建立双向关系。
- 手机 `deepen` 使用当前快照与检索片段，只能提出有证据的候选关系；材料不全则标“待全文核验”，仍不自动重写伴读、不自动升级 `process_level`。
- 已有文章、人工精读笔记和历史结果不批量重写。本次发布不清理或重试失败发送，不改变 push 的历史文件约定。

## v0.4.0：干净重跑与证据边界

#24 的真实预览暴露了四类问题：当前原文和旧伴读进入独立背景；模型把未出现的品牌/架构归给作者；业务建议没有对照与验收条件；分诊混淆了逐段阅读和业务验证价值。

检索新增 `VaultContextOptions.excludePaths` 与 `excludeSourceUrls`，`searchVaultNotes` 第五参数接受同一排除选项。初筛 pipeline 和文章精读自动传入当前文章 URL、原文路径与伴读路径。自写预览必须传同样参数，例如：

```ts
const context = gatherVaultContext(config.vaultRoot, searchText, {
  ...config.vaultLayout,
  excludePaths: [record.source_md_path, record.note_md_path].filter(Boolean),
  excludeSourceUrls: [record.url],
});
```

- 排除发生在评分、排序及前六条截取之前；候选可由其他材料补满。当前原文仍单独作为文章证据输入；旧伴读在精读阶段仅作为待复核分析，不再混入独立背景。
- 路径相对知识库根目录解析并核对真实路径，覆盖符号链接别名。frontmatter 的 `source_path` 绝对路径直接解析，相对路径基于该笔记目录；`source_url` 识别同源副本。也保护焦点/队列/主题文件误指向自身的情况。
- 微信长链接按明确的 `__biz + mid + idx` 识别同一文章；其他 URL 只去片段并排序查询参数，不删除有意义的查询值。不按标题判断，也不联网解短链。无法识别无来源元数据的任意复制内容或未知等价短链。
- 支持项目写出的 JSON 双引号字符串、简单单引号和裸值 frontmatter；不是通用 YAML 解析器。排除只使用来源字段，不把正文里普通引用本文的独立分析也全部删掉。

分析请求显式区分 `current_article_author_claims_not_verified_facts` 和 `background_only_not_article_evidence`。初筛和精读共用证据/业务验证/分诊规范：原文归属不能由背景替代，强判断要有依据；有业务关联时给出假设、正常与异常样本、对照、指标、验收及责任确认，无既定数字则写待确认。

分诊规则区分两种价值：reference 用于表达素材且暂无实质待研究问题；process_later 用于相关且待进一步阅读、对照或场景验证的实质问题；process_now 还须可追溯紧迫性；keep_raw 用于当前材料不足。不能因短文就否定业务验证价值，也不能因重要就宣布立即执行。

这些语义规则由提示词约束与实测验收，不是自动事实核查器。回归检验数据流、排除行为和请求契约；真实模型预览需另行评审，不能用 mock 通过证明任意输出可靠。

首轮修订后的真实预览已确认六个候选中不再包含当前原文和旧伴读，但仍出现转述加强、微信缺少验收条件、分诊忽略业务假设的问题，因此未判定语义验收通过。进一步要求：原文引用逐字可核，必要条件不能改成充分条件；微信和伴读均展示验证六项，信息等量的对照只改变待测因素；两种阅读价值与最终分诊自洽。用户追加一次明确授权后，最终规则已完成第二次真实模型复核（HTTP 200、无降级）。自引用排除和 process_later 分诊符合预期，微信正文包含验证六项；但语义验收仍未全部通过：转述仍有加强，试验组额外补充规则信息而未保持信息等量，失败结论越界推导为需要规则引擎，验收标准“明显改善”也未定义。不得将这次结果描述为完整通过，更不能由自动测试通过推断语义可靠。

本地验证：新增 6 项回归，全量 157 项通过；隔离审计 6 项通过，类型检查与文档链接检查通过。测试只验证确定性行为和请求契约，不自动保证模型遵守提示词。本机服务未部署本次修订。

### 后续修正：措辞强度与实验因果边界

第二次预览的遗留问题促使我们检查规范本身：原规则同时要求信息等量，又举“现有输入 vs 补充规则”的例子，存在冲突。本轮替换这个例子，初筛与精读统一采用以下规则：

- 忠实保留原文的频率、范围和条件，“往往”不能转述为“根本原因”。作者把多个概念放在一个框架中，不足以证明执行职责混淆；原文未展开不等于做错。推演必须标为分析判断并交代触发条件，不为观点碰撞强造反驳。
- 测**表达结构**：先冻结同一份业务确认的事实与规则清单，A 组自然语言段落、B 组结构化字段；逐条核对定义、规则、例外、示例，模型、参数、工具、案例与运行次数保持一致。不得只给 B 组补规则后归因于表达结构。
- 测**信息补充**：披露 B 组新增的规则，表达形式保持一致；只讨论补充信息的收益，不据此证明结构化表达或某种本体架构更有效。
- 运行前约定可判断的验收标准，指标明确分子分母及改善门槛，未批准数字标为建议待确认。不能只写“明显改善”，也不能把小样本方向性结果称为统计显著。
- 未观察到增益只涉及本次样本、模型、规则与配置，不能推出必须使用规则引擎、其他未比较方案更优或方法普遍无效。信息不等量、样本或标注不足属于证据不足/试验无效；通过也只支持在该范围继续验证。

新增三项请求契约回归，使用合成材料覆盖上述已复现缺口；已有精读测试同时核对共享规则传入。真实 Gemini 验证单独记录，不用请求文本断言冒充输出质量测试。

本轮验证：新增三项回归先失败后通过；最终全量 160 项、863 个断言通过，类型检查通过，隔离审计 6 项、37 个断言通过。全局 Skill 与仓库模板同步，未部署或发布。

用户授权的第三次 Gemini 预览只调用一次，材料快照与上一轮一致（6 个候选、7 条背景），HTTP 200，无降级。微信和临时伴读均保留作者限定词、把实现风险作为分析判断、明确等量信息的表达结构对照，失败不再越界推导架构必要性，分诊为 process_later。原文、旧伴读、文章记录、发送队列与部署文件经只读比较均未变，3 条失败记录保留。

本轮仍未达到实验方案可直接执行的完整语义验收：模型把差值小于 5% 当作波动/显著性边界，缺少重复测量或统计依据；同一建议门槛在微信写相对提升、临时伴读写绝对提升，口径不一致。因此仅确认本轮主要缺陷在该样例中改善，不能宣称统计有效或对任意输出可靠。未继续调用模型，未将预览写回笔记或微信。

### 统计口径统一与紧凑初筛（v0.4.0）

针对第三轮暴露的两份正文口径漂移，初筛新增单一 `validation_contract`，由 `src/vault/validation_contract.ts` 校验并渲染同一个统计段落，再插入微信与伴读。模型只负责一次选择指标和建议门槛，不分别撰写两套公式。无业务试验时返回 `null`；有试验时使用以下结构，并在两份正文的业务验证部分各保留一次 `{{VALIDATION_CONTRACT}}`：

```json
{
  "metrics": [{
    "name": "准确率",
    "numerator": "正确判定样本数",
    "denominator": "有效样本总数",
    "direction": "increase",
    "minimum_gain": {"unit": "percentage_points", "value": 5}
  }]
}
```

- 支持1–3个比率指标，手机优先只选一个；`direction` 为 increase/decrease，改善单位为 percentage_points/relative_percent。`value` 为非负建议改善门槛，百分点不超过100，null表示待定，0表示不得恶化。这不是率的绝对水平，例如“召回率达到95%”不能填成“提升95%”。
- A、B按0–1比率定义。增加型百分点差为 `(B-A)×100`，相对提升为 `(B-A)/A×100%`；下降型交换差值符号。分母为0不判定；基线A为0时相对变化不可计算，不能强行给0或无穷大。
- 全部门槛均需运行前确认；门槛缺失、未确认、分母无效时不能判通过。有效试验全部达到已确认门槛才通过，未达仅指本次范围内未达业务目标，不等于方法无效。
- 共享段落固定说明：门槛不是波动范围；未估计波动，不作统计显著性判断。没有重复测量或统计估计，不能把任意5%差值当成噪声边界或置信区间。
- 缺少 contract、非法单位/数值/方向、空指标或重复指标、插入位置缺失或重复时，沿用可见的本地摘录降级，不把不一致的结果静默送出。旧模型若不遵守新响应结构会降级，v0.4.0 增加一次契约自纠正；仍不合规则明确降级。网络瞬时故障重试与契约自纠正不同，不能假设一次分析只有一次外部调用。既有笔记不迁移。
- 同一段落的定义、单位和门槛一致性由代码保证；自由正文中的语义、模型是否绕过约定另写门槛仍需复核，不宣称代码完成了统计检验或通用事实核查。
- 代码同时要求占位符位于业务验证部分；该部分旁文重复“显著、波动范围、置信区间、百分点、相对提升/下降”等统计表述会拒绝并降级，避免共享口径之外又生成第二套判断。这是响应契约校验，不能识别所有同义改写，也不替代统计评审。
