## 文件与数据库兼容

- 新版打开数据库时，为 `reply_outbox` 增加 `media_sha256` 列。媒体快照路径是数据库同目录的 `outbox_media/<sha256>/<原文件名>`；队列的 `media_path` 指向快照。相同内容和文件名可复用，发送和重试读取固定内容。
- 旧待发媒体没有摘要，不能证明它仍是入队时的版本，因此拒绝发送并记录错误，沿用最多三次尝试。需以新的推送重新入队；文本回执不受影响。不要让旧版与新版共用数据库发送媒体，因为旧版不会校验此摘要。
- 快照当前不自动清理，会增加磁盘占用。原文、附件和历史导出不被覆盖；损坏 PDF 若需要替换，会先保留为带 `.invalid.<uuid>` 后缀的文件。
- 新会话产物路径为 JSON 数组，空产物存空串。旧单路径先按完整路径识别，含逗号也不拆分；旧逗号列表仅在各项都存在时兼容。无法可靠识别的旧记录不会猜测文件，应明确指定源文件重新发送。
- API 调用同时给出 `markdownPath` 与 `markdownContent` 时，两者必须一致，包括显式空字符串；需要新的正文应先写入新的源文件。
- `push` 明确提供历史 HTML/PDF 时仍会保留这些输入，即使同时从 Markdown 生成当前版本。新增回归固定该约定；本轮未改变文件选择语义。

## 结果与验证边界

执行结果新增可选 `outcome`：`success`、`partial`、`failed`。业务失败记录为任务 `failed`；部分完成仍使用现有 `done` 状态，但阶段及 `missingFormats` 明确说明。任务执行完成不等于微信送达，送达仍检查 outbox / `push` 返回。

PDF 校验检查文件大于 500 字节、`%PDF-x.y` 头和末尾范围内的 `%%EOF`；这能挡住此次残缺/垃圾文件复现，不等于完整 PDF 结构解析或排版验收。快照保障入队后的字节稳定，不保证导出前正在被外部修改的多文件源具有事务一致性，也不提供端到端 exactly-once。

- 修复前：初始 16 项复现回归全部失败。
- 修复后：新增 31 项回归；全量 **114 项测试、564 个断言通过**，包含 `push` 历史文件约定保护。
- TypeScript 类型检查、差异空白检查与变更文档相对链接检查通过；Spec 和 Standards 两轴复核无阻断问题。
- 测试使用临时目录、隔离环境、模拟 CLI/浏览器/模型/微信；HTTP 测试仅使用临时测试监听。未读取真实凭据、调用真实微信/模型/CLI/浏览器、操作用户知识库或部署服务，也未更新全局 Skill。真实送达、模型行为和 PDF 视觉效果不在此次验收范围。

发布门槛为上述本地验收通过，再确认发布提交的 GitHub CI 成功；发布仅涉及代码、注释标签与 GitHub Release。部署和真实数据升级由使用者另行安排。
